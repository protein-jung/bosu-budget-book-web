보수가계부 iOS 앱 출시 계획
=============================
작성일: 2026-09-21

전제: frontend/는 이미 Expo Router(Expo SDK 57, React Native 0.86) 기반이라
"웹으로 만든 걸 앱으로 새로 만드는" 게 아니라 "이미 존재하는 네이티브 앱을
처음으로 빌드해서 배포"하는 작업에 가깝다. 코드를 새로 짤 필요는 거의 없고,
설정 + 빌드 + 스토어 등록이 핵심이다.


0단계. 지금 상태 점검 (이미 확인함)
------------------------------------
- 인증 토큰 저장: src/lib/storage.ts 추상화를 통해 저장 — 네이티브에서도 그대로 동작.
- 계정 삭제 기능: settings/profile.tsx에 이미 있음 (Apple 필수 요건, 이미 충족).
- 개인정보처리방침/이용약관: /privacy, /terms 라우트 이미 있음 (스토어 등록에 필요).
- 앱 아이콘: assets/images/icon.png, 1024x1024 확인됨. 단, 알파 채널(투명)이
  있어서 iOS 빌드 시 문제 될 수 있음 → 1단계에서 알파 없는 버전 별도 필요.
- app.json에 "ios" 블록이 아직 없음 (android 블록만 있음) → 추가 필요.
- ⚠️ 중요 버그: src/lib/apiClient.ts의 resolveDefaultApiBaseUrl()이 네이티브에서
  기본값으로 http://localhost:8080 을 쓴다. 네이티브 빌드에는 .env.local이
  안 실리므로, 빌드 시점에 EXPO_PUBLIC_API_URL을 명시적으로 주입하지 않으면
  실제 아이폰에서 앱이 자기 자신의 localhost를 호출해서 전부 실패한다.
  → 3단계에서 eas.json env로 반드시 고정.

2단계. app.json에 iOS 설정 추가 — 완료
------------------------------------
app.json에 아래 "ios" 블록을 추가함 (실제로 반영됨):

  "ios": {
    "bundleIdentifier": "com.bosuledger.app",
    "buildNumber": "1",
    "supportsTablet": false,
    "icon": "./assets/images/icon-ios.png",
    "infoPlist": {
      "ITSAppUsesNonExemptEncryption": false
    }
  }

- bundleIdentifier는 "com.bosuledger.app"으로 정해서 넣어둠 — 앱스토어에 한 번
  등록하면 변경 불가하니, 다른 값을 원하면 첫 빌드(eas build) 전에 바꿀 것.
- ITSAppUsesNonExemptEncryption: false로 "표준 HTTPS 외 독자 암호화 안 씀" 선언 완료
  — 매 제출마다 App Store Connect에서 수동으로 묻는 걸 방지.

알파 채널 없는 아이콘도 생성 완료: assets/images/icon-ios.png
(원본 icon.png는 투명 배경이라 iOS 아이콘 규정에 안 맞아서, 앱 배경색
#F4EBDD로 채운 불투명 버전을 따로 만들어 ios.icon으로 지정함. 안드로이드/웹은
원본 icon.png를 그대로 쓰니 영향 없음.)


3단계. eas.json 생성 및 API 주소 고정 — 완료
------------------------------------
frontend/eas.json 생성 완료. development/preview/production 3개 프로필 모두
EXPO_PUBLIC_API_URL=https://api.bosuledger.com 을 고정해서 넣어둠 — 이게 없으면
위에서 말한 localhost 버그 그대로 빌드에 들어간다.

CORS: 네이티브 앱은 브라우저가 아니라 Origin 헤더 자체가 없거나 달라 보통
CORS 정책 영향을 안 받는다 — 그래도 첫 빌드 후 실제 로그인이 되는지로 반드시
확인할 것.

EAS 프로젝트 연결도 완료: `eas init`으로 @sumin-dev/housebook 프로젝트 생성·연결함
(app.json에 extra.eas.projectId 자동 추가됨, Apple 계정과 무관하게 되는 단계라
미리 해둠).


4단계. eas build:configure — 사실상 완료 (Apple 활성화 후 확인만)
------------------------------------
eas.json과 프로젝트 연결을 이미 수동/eas init으로 끝내놔서 이 명령을 따로 또
돌릴 필요는 없음. 다만 iOS 인증서/프로비저닝 프로파일("credentials")은 EAS가
Apple Developer 계정에 실제로 접근해야 만들 수 있는데, 지금은 Apple 활성화
대기 중이라 이 부분만 막혀 있다. 활성화 메일 받으면:

  cd frontend
  eas build --profile development --platform ios

이 명령을 처음 실행할 때 Apple ID 로그인(+2단계 인증)을 요구하면 로그인만
하면 됨 — 인증서 생성은 EAS가 자동으로 처리한다("managed credentials").
Apple ID 로그인은 보안상 내가 대신 할 수 없는 부분이라 직접 진행 필요.


5단계. 첫 시뮬레이터 빌드로 빠르게 확인
------------------------------------
  eas build --profile development --platform ios

빌드가 끝나면(15~20분 정도) 링크를 iOS 시뮬레이터에 설치해서 실행.
이 단계에서 확인할 것:
- 로그인/회원가입이 실제 운영 API(api.bosuledger.com)로 붙는지
- 캘린더/통계/자산/설정 등 주요 화면이 네이티브에서 깨지는 곳 없는지
  (웹 전용으로 작성된 CSS 트릭이 있으면 여기서 드러남)
- 폰트/아이콘/스플래시 화면이 의도대로 보이는지
- 딥링크(scheme: "housebook")가 필요한 곳 있으면 동작 확인


6단계. 실기기 빌드 + TestFlight 내부 테스트
------------------------------------
  eas build --profile production --platform ios
  eas submit --platform ios --latest

- eas submit이 자동으로 App Store Connect에 업로드한다.
- App Store Connect(https://appstoreconnect.apple.com)에서 앱 레코드가
  자동 생성 안 돼 있으면 먼저 "새로운 앱" 만들어야 할 수도 있음
  (Bundle ID를 2단계에서 정한 값과 동일하게).
- 업로드 후 TestFlight 탭에서 내부 테스터(최대 100명, Apple 심사 불필요,
  몇 분~몇 시간 내 사용 가능)로 등록해서 실기기로 먼저 써본다.
- 외부 테스터를 추가하려면 Apple의 간단한 베타 심사(보통 하루 이내)가 필요.


7단계. App Store Connect 메타데이터 준비
------------------------------------
심사 제출 전에 미리 준비해둘 것들:
- 앱 이름, 부제, 설명, 키워드 (한국어)
- 스크린샷: 기기별 필수 사이즈 (6.9인치/6.5인치 등) — 시뮬레이터에서
  캡처하거나, 기존 marketing/ 폴더의 스크린샷을 아이폰 크기로 재구성
- 개인정보처리방침 URL: https://bosuledger.com/privacy (이미 있음)
- 지원 URL: 문의 받을 페이지나 이메일
- App Privacy(개인정보 "영양성분표"): 수집하는 데이터 항목을 정직하게
  체크 — 이메일, 이름, 생년월일, 금융 정보(가계부 내역)가 수집되므로
  "Financial Info", "Contact Info" 등 해당 카테고리 체크 필요.
  거짓/누락 신고되면 반려·계정 정지 사유가 될 수 있어 정확히 작성.
- 연령 등급 설문 작성
- 심사용 데모 계정 메모: 로그인이 필수인 앱이라 Apple 심사팀이 로그인할
  계정이 필요함. "App Review Information"에 테스트 계정
  (예: test@test.com / test@test.com, 기존 운영 데모 계정) 이메일/비밀번호를
  꼭 적어둘 것 — 안 적으면 로그인 벽에서 바로 반려됨.


8단계. 심사 제출 전 자체 점검 (반려 방지)
------------------------------------
가계부/금융 앱이라 특히 자주 걸리는 항목:
- 로그인 없이 앱의 가치를 보여주는 화면이 있는가 (완전한 로그인 벽만
  있으면 "Minimum Functionality" 사유로 반려될 수 있음) — 지금 웰컴
  화면이 이 역할을 하는지 재확인.
- 계정 삭제 경로가 앱 안에서 찾기 쉬운가 (이미 있음, 위치만 재확인).
- 외부 결제/구독이 없다면 상관없지만, 나중에 유료 기능을 넣을 계획이면
  Apple 인앱결제(StoreKit) 의무화 대상인지 미리 확인.
- "Sign in with Apple"은 다른 소셜 로그인(구글/카카오 등)을 제공할 때만
  필수 — 지금처럼 이메일/비밀번호만 있으면 필수 아님.
- 깨진 링크, 플레이스홀더 텍스트, 크래시 없는지 마지막 전수 확인.


9단계. 제출 및 이후
------------------------------------
  eas submit --platform ios --latest   (6단계에서 이미 했으면 생략)

App Store Connect에서 "심사를 위해 제출" 버튼 클릭. 보통 1~3일 내 결과.
반려되면 이유가 구체적으로 오니 고쳐서 재제출하면 된다 (빌드 번호만
올려서 다시 제출 가능, 새 빌드 필요 없을 수도 있음).

출시 이후:
- JS/UI만 바꾸는 수정은 매번 스토어 재심사 없이 EAS Update로 즉시 배포
  가능 (expo-updates 설치 필요, 네이티브 코드/권한 변경이 없을 때만).
- 네이티브 모듈 추가나 app.json 설정 변경은 다시 빌드+제출 필요.
- 버전 올릴 때마다 app.json의 ios.buildNumber를 증가시켜야 함
  (production 프로필에 autoIncrement: true를 넣어두면 EAS가 자동 처리).
